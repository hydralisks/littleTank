# 战前准备状态设计

## 目标

为所有关卡增加一个只由关卡入口触发的战前准备阶段。玩家从地图进入关卡，或从胜利结算点击“继续”进入下一关时，先查看敌方初始战场信息并调整当前职业构筑，再主动点击“开战”。战斗失败后的“重新挑战”不进入该阶段，继续沿用失败结算页的构筑修改后直接开战流程。

本设计只改变 EncounterScreen 的 UI 生命周期，不改变战斗引擎、自动评测、挑战关卡构筑规则或策划表数据。

## 采用方案

采用 EncounterScreen 显式阶段方案，界面层维护：

```ts
type EncounterPhase = 'preparation' | 'active'
```

- `preparation`：战斗状态已创建，但战斗时钟和引擎 tick 尚未启动。
- `active`：正常战斗进行中；暂停、胜负结算仍由现有结果状态承载。

入口需要携带来源语义，以区分地图/胜利后进入和失败重试：

```ts
type EncounterEntry = 'map' | 'victory-continue' | 'retry'
```

`map` 与 `victory-continue` 初始为 `preparation`；`retry` 初始为 `active`。其他非 UI 创建 EncounterState 的调用不受影响。

## 准备阶段行为

准备阶段创建干净的初始 EncounterState，并保持以下内容不变：

- 战斗时间固定为 `00:00`。
- 不推进敌方技能循环、读条、自动攻击、周期状态、资源回复或关卡规则。
- 不消耗怒气/资源，不产生仇恨，不触发伤害、治疗、打断、驱散或被动事件。
- 主动技能按钮、快捷键和自动战斗操作不可施放；技能栏仍显示当前构筑和不可用状态。
- 敌方信息仅公开名称、初始生命值、站位和初始公开状态，不公开尚未触发的技能循环、后续读条或隐藏机制。
- 允许点击敌方血条预选开战目标；预选只更新目标指示，不触发任何战斗事件。

## 首次战备教程

每份存档第一次进入任意关卡的准备态时，先显示关卡内部的战备蒙版教程。蒙版保留敌方血条和初始公开信息作为可观察对象，并依次指出敌方信息、主动技能配置、被动天赋配置和开战按钮，说明玩家可以依据已公开信息完成战备。

- 战备蒙版教程显示期间，`开战`按钮保持禁用。
- 教程完成后才激活`开战`，玩家仍停留在准备态，可继续观察和修改构筑。
- 现有按关卡触发的战斗教程在玩家点击`开战`后显示，不与战备教程重叠。
- 战备教程每份存档只自动触发一次，使用独立的已完成标记；之后进入任何关卡都直接显示可操作准备态。
- 使用现有“重置教程”功能时，同时清除此标记，下一次进入准备态重新触发。
- 失败后的“重新挑战”直接进入战斗，不触发战备教程。

## 构筑配置

准备阶段开放现有主动技能配置面板和被动天赋配置面板，关闭面板后仍停留在准备阶段。配置修改实时刷新玩家面板可观察内容，包括最大生命值、当前生命值上限、怒气上限及可预览的被动状态；不得推进敌方状态、时间、冷却或战斗事件。

点击“开战”时，应使用当前已确认构筑重新生成或重置为干净的初始 EncounterState，避免配置预览或面板挂载产生运行时残留。

## 遮罩按钮与状态矩阵

不调整现有战斗界面主要区域的位置关系。非战斗态新增的三个按钮叠放在玩家技能按键区域的上层，使用填充材质与战斗界面区分，并缩小尺寸以避免遮挡敌方血条。

按钮固定为两个字：`返回`、`开战`、`继续`。

| 界面状态 | 返回 | 开战 | 继续 | 继续语义 |
| --- | --- | --- | --- | --- |
| 战前准备（教程中） | 可用 | 灰色不可用 | 灰色不可用 | 无 |
| 战前准备（教程完成） | 可用 | 可用 | 灰色不可用 | 无 |
| 战斗进行中 | 按现有暂停/返回规则 | 灰色不可用 | 暂停菜单打开时可用 | 继续战斗 |
| 暂停菜单 | 可用 | 灰色不可用 | 可用 | 继续战斗 |
| 胜利结算 | 可用 | 灰色不可用 | 可用 | 进入下一关战前准备 |
| 失败结算 | 可用 | 灰色不可用 | 灰色不可用 | 无；构筑修改后使用“重新挑战”直接开战 |

现有失败结算中的“重新挑战”保留其原语义，不改名为“开战”；本设计中的三个统一按钮只覆盖战斗遮罩和准备/结算导航区域。

## 流程

1. 地图点击“进入这一关”：加载关卡和当前职业构筑，进入 `preparation`。
2. 玩家查看敌方初始信息，可预选目标，打开并提交主动技能/被动天赋配置。
3. 如果是本存档首次准备态，先完成战备蒙版教程；教程完成前不能点击“开战”。
4. 点击“开战”：锁定当前构筑，生成干净初始 EncounterState，切换 `active`，再按现有规则显示本关战斗教程并启动 tick。
5. 战斗中按现有规则暂停、胜利或失败。
6. 胜利结算点击“继续”：加载下一关并进入 `preparation`，不直接开战。
7. 失败结算点击“重新挑战”：使用当前构筑直接进入 `active`，不显示准备阶段。
8. 准备阶段点击“返回”：返回地图，不记录未提交的战斗运行时状态；已提交的职业构筑仍按现有持久化规则保存。

第一章教程 RD-1~6、普通主线和挑战关卡全部适用。

## 自动评测与数据边界

- `createInitialEncounterState`、`tickEncounter` 和自动评测调用不增加 UI 阶段参数，不改变其现有默认行为。
- 只有 EncounterScreen 的入口层决定初始 `EncounterPhase`。
- 挑战关卡仍使用其解锁时对应的 buildRule 快照；战前准备不会绕过构筑合法性校验。
- 不生成、覆盖或重排 `public/designer-data/player_build.xlsx`。

## 熊 T 默认构筑维护

后续维护策划表时，继续为 `druid_bear_t` 保持以下规则的默认主动/被动构筑行，字段格式与战士 T 完全一致：

- `standard_5slot`
- `8slot_0`
- `8slot_2`

战前准备只读取并编辑当前职业/关卡构筑，不改变默认行的职责。默认行的具体技能、天赋和数值由熊 T 职业设计与策划表校验流程另行维护。

## 验收标准

- 地图进入和胜利后继续都先显示准备态，失败重试直接开战。
- 准备态时间保持 `00:00`，敌人血条和初始公开信息可见。
- 准备态可打开两个构筑面板，配置实时反映在玩家预览面板。
- 准备态点击敌人只改变预选目标，不产生战斗事件。
- 首次进入准备态显示战备蒙版教程，完成前“开战”禁用；完成后写入存档标记。
- 现有关卡战斗教程只在点击“开战”后显示；重置教程会同时恢复战备教程。
- 三个新增按钮叠放在技能区域上方，不遮挡敌方信息；按钮启用/禁用与状态矩阵一致。
- 点击“开战”后战斗正常推进，自动评测和非 UI 战斗测试结果不变。
