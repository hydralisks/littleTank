# 报告与开发文档中文化设计

日期：2026-07-31

## 目标

将本轮7月25日至30日开发周期涉及且尚未推送的熊 T、战斗界面和数值平衡开发文档统一改为中文文件名，并尽量使用中文标题、章节名和说明文字。把熊 T/战士 T 全关卡完整预算对比报告放入 Git 可跟踪目录，完成验证后提交并推送远程 `main`。

## 范围

- 中文化 2026-07-25 至 2026-07-30 本轮开发周期涉及、尚未推送的计划、设计和职业扩展交接文档。
- 更新仓库内指向旧英文文件名的全部引用。
- 不批量改名历史未触碰文档，避免制造与本轮无关的重命名噪音。
- 保留代码标识符、命令、关卡 ID、职业 ID 和必要英文技术名词。
- 不运行任何会生成或覆盖 `public/` 内容的脚本。

## 报告落点

- 原始评测产物继续位于 `reports/balance/`，Markdown 和 JSON 均使用中文文件名。该目录按项目规则不进入 Git。
- 可审阅报告写入 `docs/reports/熊T与战士T全关卡完整预算对比报告-2026-07-30.md`，进入版本控制并随代码推送。
- `scripts/buildFullStageClassComparison.mjs` 负责同时维护上述两个落点，避免人工复制后内容漂移。

## 文档命名规则

- 日期前缀保持 `YYYY-MM-DD-`，便于按时间排序。
- 职业名使用项目约定的“熊T”“战士T”。
- 关卡、模块和行为使用中文描述；必要的 `WF6`、`Delta` 等稳定缩写保留。
- 实施计划和设计文档分别保留在 `docs/superpowers/plans/` 与 `docs/superpowers/specs/`。

## 验证与提交

- 用契约测试锁定汇总脚本的中文输出名和受版本控制报告路径。
- 检查旧英文路径无残留、中文报告存在且内容与原始 Markdown 一致。
- 运行全量测试、lint、生产构建、策划表只读校验和 `git diff --check`。
- 将当前工作区全部改动作为一个阶段性熊 T 开发提交推送到 `origin/main`。
