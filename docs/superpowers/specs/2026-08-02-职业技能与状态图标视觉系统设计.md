# 职业技能与状态图标视觉系统设计规格

## 1. 目标

为 LittleTank 建立一套可扩展的职业技能、被动天赋与战斗状态图标语言，使玩家在 18px 至 90px 的不同显示尺寸下都能回答四个问题：

1. 这是哪个职业的效果；
2. 它来自主动技能还是被动天赋；
3. 它是有利、有害还是团队效果；
4. 它当前有多少层、还剩多少时间。

本规格先覆盖战士 T 与熊 T，并为死亡骑士 T、修补匠 T、黑龙唤魔师 T、土元素 T 预留同一套扩展接口。

## 2. 已确认的设计决策

采用“图标主体 + 语义外框 + 纹章挂饰”的分层方案。

- 图标主体表达具体技能或天赋的动作、对象与职业材质。
- 职业纹样表达效果来源职业。
- 主动技能使用小战旗形纹章挂饰。
- 被动天赋使用椭圆盾形纹章挂饰。
- 有利、有害与团队效果由状态图标整圈外框表达。
- 可叠层状态在右下角显示叠片式数字章。
- 状态剩余时间继续使用现有顺时针遮罩，不与纹章和层数争夺位置。
- 首次进入战斗界面时使用教程蒙版解释上述规则，并提供后续重看入口。

浏览器确认稿中的剑、熊抓、骷髅、扳手、眼睛、山峰和挂饰图形均为结构示意，不属于最终美术资产。当前批准的是信息结构，不是示意图的造型、笔触或材质质量。

## 3. 当前问题

现有战士 T 的主动技能大多已有独立图标，但造型、色板和状态衍生图标不在同一视觉系统内。熊 T 的 16 个主动技能几乎全部复用 `bear-claw`，多数天赋复用 `bear-leaf`，只能识别职业，无法识别具体技能。

当前状态 UI 还存在以下限制：

- `StatusBadge` 主要依据 `StatusEffect.kind` 设置背景色，未显式表达主动或被动来源。
- `StatusEffect` 已有 `stacks` 与 `maxStacks`，但 `StatusBadge` 未显示层数。
- `playerBuff`、`enemyDebuff`、`partyBuff` 等策划分类会被压缩成不完整的展示类型，不能稳定承担全部视觉语义。
- `resolveIconAssetUrl` 由调用方指定目录，未完整利用 `BuildIconDefinition.iconType`。
- 熊 T 的大面积占位复用虽然通过资产覆盖校验，但不满足技能辨识要求。
- `怒气枯竭` 等玩家负面效果的现有分类不可靠，视觉层不能把“显示位置”误当成“有利或有害”。

## 4. 视觉信息架构

### 4.1 四层结构

从底到顶依次为：

1. **主体插画层**：具体技能、天赋或状态的主轮廓。
2. **状态语义框层**：有利、有害、团队或中性状态的整圈外框。
3. **来源纹章层**：左上角的小战旗或椭圆盾，以及职业纹样。
4. **运行时信息层**：右下叠层数字、现有持续时间遮罩、冷却与充能信息。

来源纹章和叠层数字必须放在不同角落。任何一层都不得使用大面积纯黑色几何底块遮挡主体。

### 4.2 主动与被动

主动和被动描述的是状态来源，不描述持续时间。

- `activeSkill`：小战旗挂饰。无论状态持续 1 秒还是永久存在，只要由主动技能直接施加，都使用小战旗。
- `passiveTalent`：椭圆盾挂饰。常驻、条件触发或由天赋改造技能产生的状态，只要其规则所有权属于天赋，都使用椭圆盾。
- `encounter`：敌人技能、关卡词缀、特殊规则产生的状态不显示玩家职业纹样，继续使用敌方、词缀或规则自身的图标来源。
- `system`：无法归属具体技能、天赋或遭遇的系统状态使用中性外框，不伪造职业来源。

当一个主动技能因被动天赋获得额外效果时，按效果规则所有权决定来源：技能原有效果使用小战旗，天赋新增的独立状态使用椭圆盾。不得在同一角落叠放两枚挂饰。

### 4.3 状态极性与作用范围

颜色只承担状态极性与作用范围，不能作为唯一辨识手段。

| 语义 | 外框方向 | 非颜色辅助 |
| --- | --- | --- |
| 有利状态 | 青绿系高亮框 | 平滑内高光 |
| 有害状态 | 珊瑚红系高亮框 | 轻微断裂或侵蚀纹理 |
| 团队有利状态 | 暖金系高亮框 | 双层内沿 |
| 团队有害状态 | 红橙系高亮框 | 双层内沿加断裂纹理 |
| 中性或系统状态 | 冷灰系框 | 单层低亮内沿 |

最终色值在美术深化阶段确定，但必须满足：

- 在现有深色战斗 UI 上具有足够明度与色相对比；
- 18px 状态图标下仍能区分；
- 色弱模式下仍可依靠纹理、层数与挂饰形状辨识；
- 不使用一套职业色去替代状态极性色。

### 4.4 叠层与时间

- 仅当 `maxStacks > 1` 时保留右下叠层槽位。
- 当 `stacks > 1` 时显示阿拉伯数字；一层时不显示数字，避免无意义噪声。
- 数字章使用两至三片错位金属片形成厚度，不使用纯黑圆点或菱形。
- 18px 图标只保留数字和一层背片；28px 及以上显示完整叠片。
- 持续时间遮罩继续覆盖主体区域，但必须位于纹章与叠层数字之下。
- 永久状态不显示时间遮罩。

## 5. 职业纹样注册表

每个职业必须同时拥有唯一轮廓和高对比主色。颜色用于快速扫视，轮廓用于色弱与低亮环境下兜底。

| 职业 | 固定纹样 | 暂定色相方向 | 语义气质 |
| --- | --- | --- | --- |
| 战士 T | 剑 | 金橙 | 锻造、纪律、冲击 |
| 熊 T | 熊抓 | 青绿 | 本能、自然、厚重生命力 |
| 死亡骑士 T | 骷髅头 | 深红莓 | 鲜血、死亡、符文 |
| 修补匠 T | 扳手 | 电光蓝 | 机械、维修、过载 |
| 黑龙唤魔师 T | 眼睛 | 熔岩橙 | 龙焰、凝视、黑曜石 |
| 土元素 T | 山峰 | 岩层棕金 | 岩石、锚定、地脉 |

未来职业加入时必须单独完成纹样设计和对比测试，不得从现有职业纹样中只换颜色。未来职业的运行时 `classId` 由各自职业规格确定，本表只锁定展示名称、纹样和色相方向。

## 6. 战士 T 与熊 T 的主体美术方向

### 6.1 共用绘制规则

- 主体使用一个清晰动作轮廓和最多两个辅助元素。
- 18px 状态版本优先保留轮廓，不直接把 90px 技能图缩小。
- 同一技能的技能图与状态图共享核心轮廓，但允许状态图重新构图。
- 同一职业内部不得靠相同底图加文字、加号或改色来区分技能。
- 不把主动小战旗或被动椭圆盾直接画进主体资产；挂饰由 UI 统一合成。
- 图标边缘保留安全区，避免被冷却遮罩、纹章、层数与边框裁切。

### 6.2 战士 T

战士 T 使用锻钢、板甲、盾牌、战旗、重击与雷霆语言。主体以直线、斜切面、方形防御结构为主，强调重量和明确的受力方向。主色不是单一棕金，而是冷钢、暖金、赤红冲击和雷霆蓝的组合。

16 个主动技能必须拥有独立主体：

| 技能组 | 技能 | 主体方向 |
| --- | --- | --- |
| 仇恨 | 嘲讽、挑战怒吼 | 指向性剑锋与扩散战吼波纹 |
| 反制与控制 | 拳击、风暴之锤、震荡波 | 铁拳截断、投掷战锤、扇形地裂 |
| 核心防御 | 盾墙、无视苦痛、盾牌格挡、盾牌反射 | 盾阵、吸收裂纹、迎击盾面、镜面反光 |
| 伤害与资源 | 复仇、盾牌猛击、雷霆打击 | 回击弧线、盾沿撞击、雷击落点 |
| 爆发与支援 | 天神下凡、集结呐喊、援护、挫志怒吼 | 巨像轮廓、集结号角、位移护盾、压制声浪 |

16 个被动天赋也必须独立构图，但沿用战士材质族：板甲类使用铆接结构，姿态类使用人物或盾牌朝向，怒气类使用赤红流动元素，技能改造类保留关联技能的一个核心轮廓，团队类使用战旗或队列构图。最终逐项构图在美术深化阶段审定。

### 6.3 熊 T

熊 T 使用皮毛、树皮、月光、兽爪、再生与大地震动语言。主体以弧线、环抱形、抓痕和层叠自然材质为主。青绿职业纹样只用于来源挂饰；主体可使用树皮棕、月光青、治疗绿和怒气赤，避免整套图标只有棕色熊掌。

16 个主动技能必须替换当前统一 `bear-claw` 占位：

| 技能组 | 技能 | 主体方向 |
| --- | --- | --- |
| 仇恨与基础攻击 | 低吼、裂伤、痛击、横扫、咆哮 | 兽首声波、咬合爪痕、落地重击、横向爪弧、范围咆哮 |
| 反制与远程 | 迎头痛击、月火术 | 头槌截断、月牙灼痕 |
| 核心防御 | 铁鬃、树皮术、生存本能 | 层叠硬鬃、包覆树皮、巨熊心脉 |
| 治疗与生命 | 狂暴回复、明月普照、愈合 | 赤色再生旋涡、月柱与生命环、嫩芽愈合 |
| 爆发 | 乌索克的化身、沉睡者之怒、狂暴 | 熊神剪影、苏醒符文与反击环、挣脱锁链的兽爪 |

21 个被动天赋必须独立构图。生命与减伤天赋使用皮毛、树皮、熊神轮廓；怒气天赋使用赤色脉冲；月火关联天赋使用月牙；团队天赋使用兽群、林冠或环抱构图；铁鬃关联天赋必须保留鬃刺轮廓。最终逐项构图在美术深化阶段审定。

## 7. 状态图标派生规则

状态图标不是任意新画一张，也不是直接缩小技能图。

- 主动技能状态从对应技能图提取核心轮廓，并使用小战旗来源挂饰。
- 被动天赋状态从对应天赋图提取核心轮廓，并使用椭圆盾来源挂饰。
- 公共状态如 `taunted` 可以共享状态主体，但来源纹章必须使用本次施加者的职业纹样；战士施加时显示剑，熊 T 施加时显示熊抓。
- 同名主动技能与状态应保持明显亲缘关系，例如盾墙技能图和盾墙状态图共享盾阵轮廓，但状态图减少辅助元素。
- 吸收、减伤、治疗、易伤、伤害降低、控制等常见效果需要稳定的次级语义，但不能覆盖职业与来源语义。

## 8. 数据与组件边界

### 8.1 运行时来源数据

新增展示来源类型：

```ts
type StatusSourceKind = 'activeSkill' | 'passiveTalent' | 'encounter' | 'system'
```

`StatusEffect` 增加可选展示来源：

```ts
sourceKind?: StatusSourceKind
sourceClassId?: PlayerClassId
```

`stacks` 与 `maxStacks` 继续使用现有字段，不另建叠层模型。

状态创建与施加逻辑负责写入来源；UI 不从状态 ID 命名或显示位置猜测来源。公共状态必须在施加时写入动态 `sourceClassId`。

### 8.2 职业纹样注册

新增独立的职业纹章展示注册表，职责仅包括：

- `classId` 到纹样资产键的精确映射；
- 职业高对比色 token；
- 可访问名称；
- 是否已通过 18px 识别测试。

运行时查询必须精确命中。已发布职业缺少纹样时，开发与校验应报错；生产 UI 使用无职业纹样的中性状态框兜底，不能静默借用战士或熊 T。

### 8.3 组件拆分

- `StatusIconArtwork`：只渲染主体资产与时间遮罩。
- `StatusSemanticFrame`：渲染状态极性与团队范围。
- `StatusSourceEmblem`：渲染小战旗或椭圆盾及职业纹样。
- `StatusStackBadge`：渲染右下叠片数字。
- `StatusBadge`：组合以上组件，保留现有标题与尺寸接口。
- `ClassEmblemLegend`：为教程蒙版提供同一份纹样和形状组件，禁止教程另画一套示例。

技能栏继续展示具体技能图，不在每个 90px 技能图上重复叠加小战旗。小战旗和椭圆盾主要用于状态图标与教程图例；技能配置面板可在类别标题处使用同一形状，但不能遮挡技能主体。

### 8.4 资产解析

资产目录仍保持：

- `public/skill-icons/`：主动技能主体；
- `public/status-icons/`：状态、天赋、职业纹样和其他非技能主体。

解析器应依据 `BuildIconDefinition.iconType` 确定目录，调用方不再以 `preferredType` 覆盖真实类型。资产校验除“文件存在”外，还要检查战士 T 与熊 T 的主动技能不再大面积共享同一 `assetKey`。

本规格不会运行任何 `public/` 生成器。正式实施中，在用户明确批准具体资产写入步骤前，不得生成或覆盖 `public/` 和 `public/designer-data/` 内容。

## 9. 教程蒙版

### 9.1 触发与保存

- 玩家首次进入战斗界面时触发一次职业与状态图标教程。
- 新增独立保存位 `seenIconGrammarTutorial`，不能复用关卡教程完成状态。
- 旧存档迁移时默认 `false`，完成或跳过后写为 `true`。
- 暂停菜单或帮助入口提供“图标说明”重看入口；重看不修改关卡教程状态。

### 9.2 三步内容

1. **职业纹样**：解释剑代表战士 T、熊抓代表熊 T；只展示当前已发布职业，未发布职业不提前剧透。
2. **来源形状**：并排展示小战旗与椭圆盾，解释主动技能和被动天赋。
3. **状态与层数**：解释整圈颜色、右下叠片数字和顺时针时间遮罩。

教程复用现有 `TutorialOverlay` 的聚光与暂停战斗机制，并扩展 `TutorialStep`，使教程卡可以携带结构化图例。教程图例必须使用正式组件和 token，而不是截图或硬编码示意图。

目标元素不存在或尺寸为零时，沿用现有居中卡片兜底；教程不能因为某个状态当前未出现而无法继续。

## 10. 美术深化阶段

当前逻辑实现与最终美术验收分开。

1. 先实现分层组件、来源数据、教程和临时合规资产预览。
2. 在非 `public/` 的预览目录中制作战士 T、熊 T 全套候选图标和联系表。
3. 分别以 90px、28px、18px 和色弱模拟审查。
4. 用户批准具体美术批次后，才替换正式 `public/` 资产并更新策划映射。
5. 后续只替换主体和纹样资产，不改变已确认的战旗、椭圆盾、状态框、叠层和教程逻辑。

当前浏览器样稿不得直接复制为正式图标。

## 11. 错误处理与兼容

- 旧状态没有 `sourceKind` 时不显示来源挂饰，但仍显示主体、状态框和时间。
- `sourceKind` 是玩家来源但缺少 `sourceClassId` 时使用当前玩家职业补全；无法确定时使用中性无纹样挂饰并记录开发警告。
- `stacks` 超出 `maxStacks` 时展示钳制后的最大值，运行时数据问题仍由状态逻辑测试报告。
- 缺少图标资产时保留现有稳定占位回退，同时资产覆盖测试必须失败。
- 旧存档不改版本也可通过规范化补齐 `seenIconGrammarTutorial`；若实现需要改变保存结构，再由实施计划决定是否升级 schema。

## 12. 测试与验收

### 12.1 自动测试

- 来源解析：主动、被动、遭遇、系统四类精确映射。
- 公共状态：战士嘲讽显示剑，熊 T 低吼显示熊抓。
- 状态框：玩家 Buff、敌方 Debuff、团队 Buff、团队 Debuff 和中性状态映射正确。
- 叠层：一层不显示数字，多层显示并钳制，永久状态不显示时间遮罩。
- 资产：战士 T 与熊 T 每个主动技能拥有独立映射，不再全部落到 `bear-claw`。
- 教程：首次显示、完成保存、跳过保存、旧存档补齐和帮助入口重看。
- 兼容：缺少新来源字段的旧状态继续渲染。

### 12.2 视觉验收

- 在 90px 技能栏、28px主要状态和 18px 紧凑状态尺寸下检查。
- 桌面与移动宽度均不发生挂饰、层数、时间遮罩或文字重叠。
- 战士剑与熊抓只看轮廓即可区分。
- 小战旗与椭圆盾只看形状即可区分。
- 六个预留职业的色相方向互相有明显差异，但最终色值须通过独立美术审查。
- 颜色关闭或转为灰阶后，来源、主动被动和叠层信息仍可识别。
- 当前示意图的“好看程度”不作为通过标准；正式资产替换必须经过后续美术批次批准。

## 13. 非目标

- 本规格不设计死亡骑士 T、修补匠 T、黑龙唤魔师 T、土元素 T 的技能内容。
