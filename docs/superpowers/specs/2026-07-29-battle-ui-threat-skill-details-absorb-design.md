# 战斗 UI 仇恨边框、技能详情与吸收盾设计

## 目标

本次改动增强战斗界面的三类即时信息，不改变战斗数值、策划表或现有面板的位置关系：

1. 未选中敌人的绿、黄、红仇恨边框加粗到当前视觉厚度的两倍。
2. 主动技能构筑面板显示由结构化技能数据生成的基础数值摘要。
3. 玩家生命条上方实时显示当前吸收盾总量。

同时在首次开放被动天赋的 RD-4 地图教程中说明：主动技能详情展示的是天赋调整前的基础值。

## 敌人仇恨边框

- 当前实体边框保持 `3px`，仅对未选中且非空槽位的 `.enemy-frame` 增加同色 `3px` 内描边。
- 总视觉厚度为 `6px`，新增部分完全向框内延伸，不改变网格尺寸、间距或相邻敌人边界。
- 内描边继续使用 `--frame-accent`，因此安全、警告、失控和锁定状态保持各自颜色。
- 已选中敌人继续使用现有白色加动态仇恨色选中环，不叠加新的内描边。
- 空网格槽位不显示内描边；死亡敌人仍沿用死亡态颜色。
- 实现时把内描边合并进现有 `box-shadow` 声明，保留底部暗部、危险施法动画与选中态层级。

## 主动技能基础数值摘要

### 展示规则

- 摘要位于技能描述下方、作用目标和状态说明上方。
- 使用紧凑的两列标签/数值网格；每项为清晰的中文标签和格式化数值。
- 只显示有明确结构化来源且对该技能有意义的项目。`0ms` 冷却、空效果和无效数值不显示。
- 时间统一转成易读秒数，百分比统一显示为百分数，仇恨倍数显示为 `×N`。
- 多目标或主次目标数值不强行合并：使用“主目标伤害”“次要目标伤害”等语义标签。
- 多条效果出现相同事实时去重；不同事实按冷却、伤害、仇恨、减伤、治疗、吸收、资源的固定顺序排列。
- 本次不根据已选择的被动天赋实时改写摘要。该区域始终展示策划表载入后的技能基础值。

### 数据边界

新增独立的技能事实格式化模块，输入 `ActiveSkillDefinition` 与该技能已启用的 `ActiveSkillEffectDefinition[]`，输出 UI 可直接渲染的 `{ key, label, value }[]`。组件不解析技能描述文本。

通用字段直接读取：

- `cooldownMs`：技能冷却。
- `resourceCost`：资源消耗，值大于零时显示。
- `threatMultiplier`：技能效果的仇恨倍数，去重后显示。

`valueA`、`valueB` 的语义依赖 `skillLogicId`，因此由显式的逻辑注册表解释。当前战士 T 和熊 T 已有运行逻辑必须覆盖以下事实类型：

- 伤害：单体、范围、主次目标和持续伤害每跳数值。
- 减伤：全伤害、物理伤害、魔法伤害、队伍减伤和目标伤害降低。
- 治疗：固定治疗、最大生命值比例治疗、持续治疗每跳数值和队伍治疗。
- 吸收盾：固定吸收量及有效持续时间。
- 资源：技能产生的怒气或其他由效果字段明确配置的资源变化。
- 持续时间：减伤、治疗、持续伤害或护盾等效果需要上下文时显示。

若某个逻辑尚无可靠字段语义，只保留技能描述，不猜测或从文字中提取数字。以后新增职业技能逻辑时，应在同一注册表中补充事实解释。

## 玩家吸收盾条

- 在玩家生命条正上方增加固定高度的吸收盾显示层，与生命条平行且宽度基准一致。
- 从玩家当前有效增益和独立减伤状态中汇总所有 `absorbRemaining > 0` 的数值。
- 多个护盾按剩余吸收量相加；展示宽度为 `总吸收量 / 玩家最大生命值`，并限制在 `0%` 到 `100%`。
- 总吸收量超过最大生命值时，视觉保持满条，实际游戏状态和内部总量不截断。
- 总吸收量为零时不渲染白色条，也不显示空轨道；承载层保留稳定尺寸，避免战斗中生命条和文字跳动。
- 白色条使用纯白主体和轻微亮边，与绿色生命值、资源条及状态图标明确区分。
- DOM 提供包含实际总吸收量的无障碍标签，便于测试和辅助读取；不额外增加常驻可见数字。

## 教程提示

RD-4 首次开放被动天赋时，在“打开被动天赋”步骤补充：

> 被动天赋会改变你的数值、技能效果或队伍承压能力。主动技能配置中的技能详情显示天赋调整前的基础值，请结合已选天赋判断实际效果。

现有教程触发关卡、步骤数量、目标元素和面板打开顺序保持不变。

## 测试与验收

- 先为技能事实格式化模块编写失败测试，覆盖战士 T 与熊 T 的冷却、伤害、仇恨、减伤、治疗、护盾和资源样例。
- `SkillConfigPanel` 测试确认事实网格渲染、无值项目省略和基础值不受被动构筑影响。
- `PlayerStatusPanel` 测试确认单护盾、多护盾求和、超过最大生命值封顶及零护盾隐藏。
- 教程测试确认 RD-4 文案明确包含“天赋调整前的基础值”，且步骤结构不变。
- 运行相关单测、完整测试、lint 和构建。
- 在桌面/平板宽度的本地演示中人工确认：相邻敌人边框不交叉、选中环不受影响、技能事实不溢出、护盾增减时生命条位置稳定。

## 非目标

- 不修改 `public/designer-data/` 或任何技能数值。
- 不计算天赋修正后的动态技能详情。
- 不调整手机端专用布局。
- 不改变敌人血条、主动构筑面板或玩家状态面板的整体位置关系。
