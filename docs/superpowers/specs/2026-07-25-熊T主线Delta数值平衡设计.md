# 熊 T 主线 Delta 数值平衡设计

## 目标

建立第一份可复用的熊 T 数值基线，覆盖挑战1~3以及主线第二、三章；随后分别生成适合策划审阅和人工试玩的主动技能、被动天赋 Delta 报告。

## 范围

- 为第二、三章每个关卡补充熊 T 主线技能解锁快照。
- 分析12个主线关卡的战士 T/熊 T 职业平衡。
- 在熊 T 技能解锁里程碑执行定向主动技能 Delta 分析。
- 在章节入口和章节末执行定向被动天赋 Delta 分析。
- 每次接受熊 T 数值改动后重新评测挑战1~3。
- 为挑战、第二章和第三章生成可持久保存的 JSON 与 Markdown 报告。
- 验证后启动当前网页演示，供人工试玩。

当证据达到下述阈值时，本轮允许修改 `player_build.xlsx` 中的熊 T 行；不得重新平衡主线敌人，也不得覆盖无关策划行。

## 主线解锁契约

熊 T 前5个技能在 `RingingDeeps-6` 同时可用，后续技能遵循战士 T 的解锁节奏：

| 关卡 | 新解锁熊 T 技能 | 累计技能数 |
| --- | --- | ---: |
| `WestFall-1` | 狂暴回复、横扫 | 7 |
| `WestFall-3` | 月火术、树皮术 | 9 |
| `WestFall-5` | 生存本能 | 10 |
| `WestFall-6` | 无 | 10 |
| `Zul'Aman-1` | 明月普照 | 11 |
| `Zul'Aman-2` | 乌索克的化身 | 12 |
| `Zul'Aman-3` | 沉睡者之怒 | 13 |
| `Zul'Aman-5` | 愈合、狂暴、咆哮 | 16 |
| `Zul'Aman-6` | 无 | 16 |

工作簿只保存每个主线关卡新解锁的技能；`getUnlockedActiveSkillIdsForStage` 继续提供累计列表。

## 分析架构

### 基线层

对第二、三章所有关卡运行战士 T 与熊 T 的快速固定/学习策略分析。按 `(stageId, classId, buildRuleId)` 比较职业，并保留现有难度标签和职业对比规则。

### 主动技能 Delta 层

新增 `active` Delta 模式。每个解锁里程碑先生成公共合法构筑池并执行低成本筛选，再通过第二阶段配对消融评估每个已解锁熊 T 技能：

- 包含该技能的最佳合法已分析构筑；
- 不包含该技能的最佳合法已分析构筑；
- 存在性 Delta = 包含构筑通过率减去排除构筑通过率。

这种方式不指定任意替换槽位。报告必须保留两边构筑，帮助策划识别相关构筑差异；存在性 Delta 仍是构筑相关性信号，不是单槽位因果估计。

里程碑：`Challenge-1`、`WestFall-1`、`WestFall-3`、`WestFall-5`、`WestFall-6`、`Zul'Aman-1`、`Zul'Aman-2`、`Zul'Aman-3`、`Zul'Aman-5`、`Zul'Aman-6`。

### 被动天赋 Delta 层

保留现有无被动基线及单项/双项变体，但选择合法熊 T 天赋，不再回退到战士 T 列表。在 `Challenge-1`、`WestFall-1`、`WestFall-6`、`Zul'Aman-1`、`Zul'Aman-6` 运行，确保覆盖每个已解锁 Tier。

### 挑战数据加载

Delta 命令行必须同时加载主线与挑战关卡/战斗工作簿。挑战 ID 必须解析到挑战专属构筑规则、敌人布置、词缀和熊 T 技能快照。

## 采样预算

整批任务允许运行约8小时，但结论稳定后应提前停止。

1. 快速基线：全部12个主线关卡、两个职业。
2. 标准 Delta：全部已定义主动和被动里程碑。
3. 完整复跑：只处理仍然低置信的中高影响对比，或可能触发数值改动的发现。
4. 数值改动后：快速回归挑战1~3和受影响章节，并对改动技能/天赋重新运行标准 Delta。

任何命令都不得静默覆盖另一范围或另一 Delta 类型的报告。

## 调整阈值

- 主线职业平衡：章节最佳通过率平均差不超过15个百分点；没有机制理由时，单关难度差不得超过一级。
- 主动技能过度中心化候选：至少两个相关关卡的存在性 Delta 达到 `+20` 个百分点，且置信度为中/高。
- 主动技能偏弱候选：至少两个相关关卡的存在性 Delta 不高于 `-15` 个百分点，且置信度为中/高。
- 被动天赋过度中心化候选：单天赋或合法组合在至少两个里程碑提升 `+20` 个百分点。
- 被动天赋偏弱候选：至少三个未饱和里程碑没有可测收益，并有治疗、减伤、仇恨、怒气或队伍压力遥测支持。
- 0%/100% 饱和结果仅作诊断，不能单独授权调整。

只调整能够解释结果的最小熊 T 自有标量或 AI 优先级，不修改主线关卡数据强行拉齐。每项接受的改动都必须保证挑战1~3不出现 `tool_gap` 和 `strength_overflow` 标记。

## 报告输出

在 `reports/balance/` 下写入 JSON 与 Markdown 对：

- `delta-druid_bear_t-challenge-1-3-active.*`
- `delta-druid_bear_t-challenge-1-3-passive.*`
- `delta-druid_bear_t-westfall-active.*`
- `delta-druid_bear_t-westfall-passive.*`
- `delta-druid_bear_t-zulaman-active.*`
- `delta-druid_bear_t-zulaman-passive.*`
- 通过现有平衡报告路径生成的章节基线报告。

每份 Delta 报告包含采样模式、对比构筑、通过率 Delta、置信度、判断结果以及供策划阅读的强/弱/无结论摘要。

## 验证与交接

- 契约测试覆盖主线解锁节奏和 Delta 报告输出隔离。
- Delta 单元测试覆盖主动存在性比较和熊 T 天赋发现。
- 策划数据校验必须为0警告。
- 全量测试、lint、生产构建和 `git diff --check` 必须通过。
- 在职业扩展交接和更新日志中记录实测结果与剩余风险。
- 从已验证工作区启动本地演示地址；人工试玩仍是发布门槛。
